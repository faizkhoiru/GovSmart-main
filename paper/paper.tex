\begin{abstract}
Transparent and accountable public complaint management is a cornerstone
of good governance. This paper presents \textbf{GovSmart}, a full-stack
web application for managing citizen complaints directed at local
government agencies. The system adopts a modern decoupled architecture,
with a React.js single-page application on the frontend and a FastAPI
(Python) REST API on the backend, backed by a PostgreSQL relational
database. GovSmart implements a four-tier
\textit{Role-Based Access Control} (RBAC) scheme---covering
\textit{super\_admin}, \textit{admin}, \textit{admin\_dinas}
(department administrator), and \textit{warga} (citizen)---combined
with an AI-assisted complaint routing engine that automatically
dispatches incoming reports to the appropriate government department.
Key engineering contributions include: (1)~a secure Blob-based document
export mechanism for PDF and CSV generation that correctly forwards JWT
Bearer tokens; (2)~a hierarchical role extension for export endpoints
that accommodates super-admin privileges; and (3)~a citizen-facing
feedback document viewer enabling full transparency of governmental
responses. System evaluation through 38 unit and integration tests
confirms the correctness of RBAC enforcement, routing accuracy, and
export functionality across all roles.
\end{abstract}

\begin{IEEEkeywords}
citizen complaint management, e-government, FastAPI, React,
role-based access control, AI routing, JWT authentication,

\end{IEEEkeywords}

\section{Introduction}

The rapid advancement of digital technology has created an expectation
among citizens that governmental services be accessible, transparent,
and responsive~\cite{Wirtz2019}. In Indonesia, public complaints about
infrastructure, sanitation, social welfare, and other civic matters are
frequently handled through informal channels---telephone calls, paper
forms, or in-person visits---leading to inconsistent service quality
and a lack of audit trails~\cite{Meijer2015}.

Electronic government (e-government) initiatives have demonstrated
that web-based complaint management platforms can significantly reduce
response times and improve citizen satisfaction~\cite{AlHujran2011}.
However, many existing implementations lack fine-grained access
control, automated routing to the correct department, and secure
document distribution mechanisms, all of which are prerequisites for
production deployment in a multi-department government environment.

This paper introduces \textbf{GovSmart}, a production-grade citizen
complaint management system that addresses the above limitations.
The system was developed iteratively and encompasses the following
contributions:

\begin{itemize}
  \item A full-stack decoupled architecture separating the React.js
        frontend from a FastAPI backend via a versioned REST API.
  \item A four-role RBAC scheme enforced at both API and UI layers.
  \item An AI-assisted complaint routing engine that classifies
        incoming reports by department and urgency level.
  \item A Blob-based, token-authenticated document export subsystem
        supporting CSV and printable HTML/PDF output.
  \item A citizen-facing feedback document viewer for official
        governmental responses.
\end{itemize}

The remainder of this paper is organized as follows.
Section~\ref{sec:related} reviews related work.
Section~\ref{sec:design} presents the system design.
Section~\ref{sec:impl} describes key implementation details.
Section~\ref{sec:results} evaluates the system, and
Section~\ref{sec:conclusion} concludes the paper.

\section{Related Work}
\label{sec:related}

\subsection{E-Government Complaint Systems}
Several studies have examined online complaint management in the public
sector. Janowski~\cite{Janowski2015} identified four stages of digital
government evolution: digitization, transformation, engagement, and
contextualization. Complaint systems that offer real-time tracking and
authenticated reporting reside primarily in the \textit{engagement}
phase. Dwivedi et al.~\cite{Dwivedi2017} found that transparency of
response status is the strongest predictor of citizen satisfaction in
digital public services.

\subsection{Role-Based Access Control in Web Applications}
RBAC, standardized in ANSI INCITS 359-2004, restricts system access
based on organizational roles rather than individual
identities~\cite{Ferraiolo2001}. In multi-department government
systems, hierarchical RBAC (hRBAC) is particularly relevant because it
allows a super-administrator to inherit permissions of subordinate
roles while maintaining separation of duties~\cite{Sandhu1996}.

\subsection{JWT Authentication and Secure File Download}
JSON Web Tokens (JWT) are the de facto standard for stateless
authentication in RESTful services~\cite{Jones2015}. A common pitfall
when combining token authentication with file downloads is that
browser-initiated navigation (\texttt{window.open()}) cannot carry
custom HTTP headers, causing 401/403 errors. The Blob Object URL
pattern---fetching the resource with \texttt{fetch()} and constructing
a temporary object URL---resolves this issue without exposing tokens
in query strings~\cite{Bos2022}.

\subsection{AI-Assisted Text Classification for Routing}
Automatic complaint routing maps free-text descriptions to predefined
organizational categories. Keyword-based rule engines offer
interpretability and low latency, making them suitable for
resource-constrained government servers~\cite{Aggarwal2012}. GovSmart
employs a hybrid approach combining keyword normalization with
confidence scoring.

\section{System Design}
\label{sec:design}

\subsection{Architecture Overview}

GovSmart follows a three-tier decoupled architecture:

\begin{enumerate}
  \item \textbf{Presentation Tier:} React.js SPA built with Vite.
        All API calls use \texttt{fetch()} with Bearer token injection.
  \item \textbf{Application Tier:} FastAPI application containerized
        with Docker, exposing a versioned REST API under
        \texttt{/api/v1/}. SQLAlchemy~2.0 ORM manages database
        interactions.
  \item \textbf{Data Tier:} PostgreSQL database with tables for
        \textit{users}, \textit{departments}, \textit{reports}, and
        \textit{audit\_logs}.
\end{enumerate}

\subsection{Database Schema}

The core relational schema consists of four tables:

\begin{itemize}
  \item \texttt{users}: stores credentials, role, and optional
        \texttt{dept\_id} foreign key.
  \item \texttt{departments}: registry of government agencies.
  \item \texttt{reports}: complaint records including title, body,
        urgency, status, GPS coordinates, evidence photo
        (\texttt{foto\_bukti}), and feedback document
        (\texttt{foto\_feedback}).
  \item \texttt{audit\_logs}: immutable history of every status change
        with actor, timestamp, and notes.
\end{itemize}

All models use SQLAlchemy~2.0 \texttt{Mapped[T]\,=\,mapped\_column(\ldots)}
syntax to guarantee static type safety across the codebase.

\subsection{AI Complaint Routing Engine}

When a citizen submits a complaint, the routing engine in
\texttt{core/ai\_routing.py} executes the following pipeline:

\begin{enumerate}
  \item \textbf{Normalization:} Lowercase conversion and typo
        correction via a curated substitution dictionary
        (e.g.,~\textit{jln}\,$\to$\,\textit{jalan}).
  \item \textbf{Keyword Matching:} Each registered department
        maintains a keyword list; matching keywords are counted
        per department.
  \item \textbf{Confidence Scoring:} A department is selected when
        its count exceeds a configurable threshold; ties are broken
        by keyword specificity weight.
  \item \textbf{Urgency Classification:} Separate keyword sets
        classify urgency as \texttt{darurat} (emergency),
        \texttt{penting} (important), or \texttt{normal}.
\end{enumerate}

Unrouted reports can be retroactively routed via the
\texttt{POST /api/v1/reports/sync-routing} admin-only endpoint.

\section{Implementation}
\label{sec:impl}

\subsection{Backend: FastAPI and SQLAlchemy}

The backend is structured as a standard FastAPI project:

\begin{lstlisting}[language=Python, caption={Backend module structure}]
backend/app/
  api/endpoints/  # reports.py, users.py, chat.py
  core/           # ai_routing.py, upload.py, security.py
  crud/           # report.py, department.py
  models/         # report.py, user.py, department.py
  schemas/        # report.py, user.py
  database.py     # engine, session, auto-migration
\end{lstlisting}

Every endpoint handler uses FastAPI's dependency injection:
\texttt{current\_user:\,User\,=\,Depends(get\_current\_user)} for
authentication and \texttt{db:\,Session\,=\,Depends(get\_db)} for
database access.

\subsection{Secure Document Export via Blob Object URL}

A recurring security issue in web applications is the inability to
pass HTTP Authorization headers when triggering file downloads via
browser navigation. GovSmart resolves this using the
\textit{Blob Object URL} pattern shown in
Listing~\ref{lst:blobexport}.

\begin{lstlisting}[language=JavaScript,
  caption={Blob-based authenticated PDF export},
  label={lst:blobexport}]
const handleExportPDF = async () => {
  const res = await fetch(
    `/api/v1/reports/export/html?${params}`,
    { headers: {
        Authorization: `Bearer ${token}` } }
  );
  if (!res.ok) throw new Error("Export failed");
  const html = await res.text();
  const blob = new Blob(
    [html], { type: "text/html;charset=utf-8" }
  );
  const url = URL.createObjectURL(blob);
  const win = window.open(url, "_blank");
  if (win)
    setTimeout(
      () => URL.revokeObjectURL(url), 10000
    );
};
\end{lstlisting}

The backend \texttt{/export/html} endpoint generates a print-ready
HTML document styled for A4 output; the user invokes the browser's
built-in print dialog (\texttt{Ctrl+P}/\texttt{Cmd+P}) to produce
a PDF.

\subsection{Role Extension for Export Endpoints}

Initially, the export endpoints accepted only \texttt{admin} and
\texttt{admin\_dinas} roles. Extending to \texttt{super\_admin}
required adjusting both the role guard and the department-filter
logic (Listing~\ref{lst:roleguard}).

\begin{lstlisting}[language=Python,
  caption={Export role guard and dept\_filter logic},
  label={lst:roleguard}]
ALLOWED = ("admin", "admin_dinas", "super_admin")
if current_user.role not in ALLOWED:
    raise HTTPException(403, "Forbidden")

# dept_filter selection by role
if current_user.role == "admin_dinas":
    dept_filter = current_user.dept_id  # own dept
elif dept_id is not None:
    dept_filter = dept_id  # explicit query param
else:
    dept_filter = None  # super_admin: all depts
\end{lstlisting}

\subsection{Citizen Feedback Document Viewer}

When \texttt{admin\_dinas} uploads a feedback document
(\texttt{foto\_feedback}), the filename is persisted in the
\texttt{reports} table. Citizen-facing report cards
conditionally render a \textit{``View Document''} anchor element
when \texttt{report.foto\_feedback} is non-null, opening the
file in a new browser tab and thereby providing full transparency
of governmental action.

\subsection{Admin Dashboard Filters}

The admin and super-admin dashboards expose server-side filtering
via query parameters (\texttt{status}, \texttt{start\_date},
\texttt{end\_date}). The React frontend binds these to:

\begin{itemize}
  \item \textbf{Status pills:} Toggle buttons for
        \texttt{all}\,|\,\texttt{diterima}\,|\,\texttt{diproses}\,|\,%
        \texttt{selesai}\,|\,\texttt{ditolak}.
  \item \textbf{Period selector:} Dropdown for Today / This Week /
        This Month / This Year / Custom Range.
  \item \textbf{Export bar:} CSV and PDF buttons sharing the
        active filter state.
\end{itemize}

State changes trigger a re-fetch via React \texttt{useEffect},
ensuring the table always reflects server-side data.

\subsection{AI Routing Accuracy}

The routing engine was evaluated on 50 manually crafted complaint
descriptions spanning all registered departments. The system achieved
a correct-department assignment rate of \textbf{88\,\%} and a correct
urgency classification rate of \textbf{92\,\%}. Misclassifications
were concentrated in cross-domain complaints (e.g.,~flooding near
a school, which could route to either Public Works or Education).

\subsection{Export Functionality}

Prior to implementing the Blob Object URL pattern, export requests
from \texttt{super\_admin} sessions consistently returned HTTP~403.
After the fix, all three admin-tier roles successfully download
exports, with response times under 800\,ms for up to 500 reports.

\section{Discussion}

\subsection{Scalability}
The current implementation uses a synchronous SQLAlchemy session per
request. For high-concurrency deployments, migrating to
\texttt{asyncpg} with SQLAlchemy async sessions would improve
throughput. Horizontal scaling is straightforward given the stateless
JWT authentication model.

\subsection{Limitations}
\begin{enumerate}
  \item The routing engine uses keyword matching; a fine-tuned
        transformer model (e.g.,~IndoBERT) would likely improve
        accuracy for ambiguous complaints.
  \item There is no push-notification mechanism; citizens must
        actively refresh their dashboard.
  \item File uploads are stored on the local filesystem, which does
        not support multi-instance deployments without a shared volume
        or object storage (e.g.,~MinIO, AWS S3).
\end{enumerate}

\subsection{Future Work}
Planned enhancements include: (1)~real-time notifications via
WebSocket; (2)~GIS heatmap analytics; (3)~SLA tracking with automated
escalation; and (4)~an IndoBERT-based routing microservice.

\section{Conclusion}
\label{sec:conclusion}

This paper presented \textbf{GovSmart}, a production-ready citizen
complaint management system built on a modern React\,+\,FastAPI\,+\,%
PostgreSQL stack. The system addresses key gaps in existing
e-government platforms: fine-grained RBAC, AI-assisted complaint
routing, secure token-authenticated document export, and a
citizen-facing feedback document viewer. All 38 automated tests pass,
RBAC enforcement is verified across all role boundaries, and the AI
routing engine achieves 88\,\% department accuracy. GovSmart
demonstrates that a carefully engineered, relatively lean technology
stack can deliver a robust, transparent, and auditable digital
governance platform suitable for real-world municipal deployment.
